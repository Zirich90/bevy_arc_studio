# Stage 11 prompt — «операторы»

Идея (паттерн Blender, без чужого кода): каждое действие это именованный оператор со схемой параметров и флагом undoable. UI и MCP идут через один и тот же путь.

Известные пробелы после этапа 10:
- Правки компонентов через Reflect не откатываются (нет undo).
- Нет add/remove component и reparent как команд.
- Не редактируются list/map/Option/Handle.
- Duplicate не работает для процедурных пропов.
- StudioCommand это enum без самоописания, ответы идут строкой в лог.
- Адресация по числовым id, которые меняются после пересборки террейна.

Задача:
1. Реестр операторов: имя, JSON-схема параметров, undoable. Команда `Describe` отдаёт схему всех операторов.
2. Типизированные ответы на команды вместо строки в логе (канал или ресурс с результатом, читаемый через BRP).
3. Undo/redo правок компонентов через единый стек (в т.ч. из Reflect-инспектора).
4. `DescribeScene`: сущности, иерархия, ключевые компоненты, bounds, выбор, одним вызовом.
5. Команды AddComponent, RemoveComponent, Reparent по имени типа через Reflect.
6. Стабильная адресация объектов по пути или имени в дополнение к id.

Порядок: сохранить промпт; прочитать mcp_commands.rs и ui_reflect.rs точечно, предложить план; реализовать; cargo check (с pf2e и без), cargo test, живая проверка BRP; скриншот в docs/screenshots/; лог в docs/clean_room_audit/logs/stage_11_log.md; перед PR спросить.
